# ctx 0.8.0: The Look Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give ctx the shared look of agent-pulse, waypoints and subagent-progress: palette colours that shade, the Tide water in its bars, four effects that mean something, and an SVG bar on Desktop.

**Architecture:** The pure rules go in small modules tested without the engine: `palette.ts` (copied palettes, `resolveLook`, the category → colour map, breaths), `fmt.ts` (`bandCells`, a `barRuns` that takes colours and water), `tide.tsx` (the frame rule `frameAt`, plus the `Client` that plays it), and `svg.ts` (the Desktop sources). `register.tsx` resolves the look, records the effect events in `$.state` atoms, and draws. The hooks never run per frame: on the terminal a `Client` plays the motion on its frame clock, and on Desktop CSS does.

**Tech Stack:** TypeScript/TSX hooks on the `claude-code` engine API, tests on `claude-code/testing`, run with `claude plugin test ctx`.

**Spec:** `ctx/DESIGN.md`, section "0.8.0: the look (design)" (committed `0710413` on branch `ctx-look`). Read it before any task. It is the source for every value below.

## Global Constraints

- The band's bar is always **16 cells, or 8 under 70 columns**, whatever it draws. Nothing changes the band's width or height.
- Water glyphs are ASCII `~` and `≈` (U+2248) only, never `∼` (U+223C).
- Levels: growth glow `subtle` + `full`; breathing `subtle` + `full` (`off` draws it still in the hot colour); compaction sweep `full` only; foam lap `subtle` + `full`; water drift `full` only; sparkline pulse `subtle` + `full`. `off` starts no clock and mounts no `Client`.
- Timings (to be tuned by eye in Task 8): frame `100` ms; foam lap `1000` ms; drift step `600` ms; growth glow `1500` ms; sweep `1200` ms; breath cycle `2000` ms.
- `claude` and `mono`: the engine's theme keys and `·` free space, no shading and no water, but **whole cells, at least one each** in the band, and the effects still play in `sparkle` / `heat`.
- No change to any figure, threshold or copy. `fillColor` (green/amber/red) and the pace's colours stay as they are.
- `follow` reads the `$.config.list()` rows `agent-pulse.palette` and `agent-pulse.animation`, falling back to `ember` / `subtle`. There is no new timer for it: refresh at `session.start`, in `config.set`, and inside the existing pane ticker and pace tick callbacks.
- One-shot effects carry an event id. Hooks pass a one-shot to a `Client` or SVG only while it is live (`now − at < duration + 300` ms), so a redraw, a hot reload or a resume never replays one.
- Version `0.8.0` in `ctx/.claude-plugin/plugin.json`, `ctx/hooks/version.ts`, and the `ctx` row of `SETUP.md`.
- A `Client` module (`tide.tsx`) imports nothing from the mod's other files: the hooks precompute every colour it needs.
- Git: branch `ctx-look`, then a PR to `master`. The person merges.
- Shell on this PC: never call `python3`, which is a Store stub that hangs for 2 minutes.

## Review Focus

1. **A category comes or goes between turns** (Skills drops to 0, Custom agents appears): the other categories keep their colours, because colour goes by name, not by position. Pinned in Task 2.
2. **No count yet, or an empty window** (`total` 0, or `max` 0): `bandCells` returns all water and does not throw, and the band still draws `Context window`. Pinned in Task 3.
3. **A full window with no free cells** (≥ 99%, buffer only): there's no foam, the breathing falls on the last used cell, and the growth span stays inside the bar. Pinned in Tasks 3 and 5.
4. **A hot reload or `/resume` just after an event:** the remounted `Client` must not replay the glow or the sweep. Pinned in Task 5 (a one-shot older than its window is not passed).
5. **`$.config.list()` throws, or agent-pulse has two installs with different palettes:** `follow` resolves to the first row with the key, or `ember` / `subtle`, and never throws out of `session.start`. Pinned in Task 2.

### Task 3: The band's whole cells, and colours and water in the exact bar

**Files:**
- Modify: `ctx/hooks/fmt.ts`, `ctx/hooks/fmt.test.ts`

**Interfaces:**
- Consumes: `Tint` from Task 2.
- Produces:
  - `type Cell = { ch: string; color: string; bg?: string; dim?: boolean; scope: string }`
  - `bandCells(snap: CtxSnapshot, width: number, tints: Record<string, Tint>, water?: { water: string; foam: string }): Cell[]`: exactly `width` cells, in `barSegments` order.
  - `edgeOf(cells: Cell[]): number`: the index of the first free cell, or `-1`.
  - `barRuns(snap, width, tints?, water?)`: the exact eighth-block bar as before. With `tints`, it takes each row's `core` (and `bg` from the next row's `core`). With `water`, free cells are `~` (`dim`, `water`) and the first free cell is `≈` (`foam`). Without either, the output is today's, byte for byte.

`bandCells` algorithm (the part a signature doesn't fix):
1. Give each segment its ideal share, `tokens / max × width`, rounded by largest remainder so that the shares sum to `width`.
2. Raise every used row with tokens > 0, and the buffer when present, to at least 1 cell. Take each raised cell from the largest segment at that moment: free space first, then the largest used row. The sum stays `width`.
3. If the minimums exceed `width`, drop the minimum of the smallest used rows, in order, until they fit. A dropped row folds into its left neighbour's cells.
   Worked example for `snap1M_8pct` at 16: the ideal shares are Messages 1, buffer 1, free 14 (the others round to 0). Raising System prompt, System tools and Memory takes 3 from free, leaving free at 11.

Glyphs: used and buffer cells as today (`█`, `░`). Free cells are `·` (`inactive`, `dim`) without `water`, else `~` / `≈` as in `barRuns`. Each used row's cells shade `core → glow` across its own cells (`mix(core, glow, i / (n − 1))`, hex only; for a theme key, `core`). `scope` is the row's name.

### Task 4: The Tide `Client` and its frame rule

**Files:**
- Create: `ctx/hooks/tide.tsx`, `ctx/hooks/tide.test.ts`

**Interfaces:**
- Consumes: `Cell` from Task 3. `tide.tsx` redeclares the type locally, since it may import nothing from the mod.
- Produces:
  - `type TideProps = { cells: Cell[]; level: 'subtle' | 'full'; edge: number; lap?: string[]; drift?: string; breathe?: { at: number[]; colors: string[] }; growth?: { id: number; from: number; to: number; colors: string[] }; sweep?: { id: number; from: number; to: number; water: string; foam: string } }`
    - `lap`: the foam's colours, core then glow.
    - `drift`: the brighter `~`'s colour, used only at `full`.
    - `growth`: `from` inclusive, `to` exclusive.
    - `sweep`: runs from `to − 1` down to `from`.
  - `frameAt(props: TideProps, frame: number, starts: { growth?: number; sweep?: number }): Cell[]`, pure and exported. `starts` holds the frame at which each one-shot began.
  - The default export, `ClientModule<TideProps, { frame: number; growthId?: number; growthAt?: number; sweepId?: number; sweepAt?: number }>`:
    - It starts one `surface.every(100)` the first time it is called with `state` undefined.
    - When `props.growth.id` / `props.sweep.id` differs from the state's, it records the current frame as that one-shot's start, in one `setState`.
    - It draws `frameAt` as one `Text` per run of equal colour, keeping each cell's `scope` as `hover={{ scope: 'ctx:' + scope, inverse: true }}`.
    - It starts no clock when there is nothing to move: no `lap`, no `breathe`, no live one-shot.

`frameAt` rules (constants in frames of 100 ms): `LAP = 10`, `DRIFT = 6`, `GROWTH = 15`, `SWEEP = 12`, `BREATH = 20`.
- Foam: at `edge`, the glyph alternates `≈` (even half of `LAP`) and `~` (odd half), and the colour is `lap[half]`.
- Drift (`full` only): free cell `edge + 1 + (⌊frame / DRIFT⌋ mod freeCount)` takes `drift`.
- Breathing: each index in `breathe.at` takes `breathe.colors[frame mod colors.length]`.
- Growth: while `frame − start < GROWTH`, cells `from…to−1` take `growth.colors[(i + frame) mod n]`.
- Sweep: while `frame − start < SWEEP`, the crest is at `to − 1 − round((frame − start) / SWEEP × (to − from))`. Cells from the crest to `to − 1` turn to water `~`, the crest is `≈` in `foam`, and cells before the crest stay as they are.
- Precedence: sweep, then growth, then breathe, then foam and drift.
